# V31 — Retained probe-operator recursion precommit

## Question

Can the frozen developmental runtime take the natural successor residual emitted by V30, reuse a probe operator learned and retained from the first epistemic development step, and thereby create a second useful experiment without a human handoff?

## Frozen starting point

- Base runtime: PR #61 / V30 developmental runtime integration.
- Natural SAIR development corpus: official Stage-2 `normal + hard1 + hard2` rows.
- Starting observational cell: the V30 cell with base signature `(0,0,0,0,0,1)` and 156 worlds.
- Initial probe language: only `MODEL_EXISTS(2,FORWARD)` and `MODEL_EXISTS(2,REVERSE)`.
- Initial generic mutation substrate: `EDIT_INT(-1)`, `EDIT_INT(+1)`, and direction flip around the order-2 seeds. No semantic `SUCC` or `ORDER3` constructor is available.
- Initial capability language: `ACCEPT_COUNTERMODEL_WITNESS` and the nonterminal `ADVANCE_PROOF_SEARCH_FRONTIER`.

## Required causal trace

The runtime must produce the following chain without experiment-specific routing:

1. `E^up = empty` and `J_P(E)=infinity` under the old probe language.
2. Generic runtime route: `DEVELOP_PROBES`.
3. Generic AST mutation produces a useful order-3 model-existence probe.
4. The runtime induces and retains the structural law `NUMERIC_LITERAL_SHIFT:+1` from that successful extension.
5. The order-3 probe is executed through the verifier and refines the version space.
6. On an order-3-negative branch, `ADVANCE_PROOF_SEARCH_FRONTIER` is selected as a common lawful nonterminal continuation.
7. Its first-class successor state is routed again by the same runtime and must return `DEVELOP_PROBES`.
8. The retained `+1` operator, rather than a newly supplied order-4 constructor, is instantiated on the current order-3 probe to synthesize `MODEL_EXISTS(4,...)`.
9. The order-4 probe is verifier-executed, the version space is updated from that verified result, and a downstream common continuation is recomputed.
10. Removing the retained operator from the V30 successor state must block that second order-4 epistemic transition under the unchanged raw mutation substrate.

## Preregistered gates

1. Official SAIR development rows are used (`1269`).
2. The exact frozen V30 base cell exists with size `156`.
3. Stage 1 starts with router-selected `DEVELOP_PROBES`.
4. The first useful probe is induced from generic AST edits and contains no semantic `SUCC`/`ORDER3` constructor.
5. The runtime itself retains `NUMERIC_LITERAL_SHIFT:+1`.
6. The first probe is load-bearing for the subsequent nonterminal action.
7. The first continuation is terminal `NONE`.
8. The emitted successor state routes back to `DEVELOP_PROBES`.
9. The second synthesized probe is order 4 and is generated by reusing the retained operator on an order-3 probe.
10. The operator is not re-learned at stage 2.
11. The second probe updates the version space only through a verifier-certified transition.
12. A downstream common continuation is recomputed after that update.
13. A distinct first-class successor state is reached.
14. Retained-operator ablation blocks the second order-4 probe.
15. The second transition depends on retained epistemic history.
16. Every encountered SAT witness is independently rechecked and no queried bounded-model call used for routing is `unknown`.
17. Protected SAIR answer labels do not enter routing, synthesis, incidence, or state update.

The umbrella gate is `V31_RETAINED_PROBE_OPERATOR_RECURSION_GATE`.

## Claim boundary

A pass would establish bounded natural-domain recursive reuse of a verifier-induced retained probe operator inside the generic developmental runtime. It would **not** establish invention of the generic mutation primitives (`EDIT_INT`, direction flip), unrestricted probe-grammar invention, broad SAIR solver generalization, or long-horizon autonomous development.
