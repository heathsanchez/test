# V31 — runtime probe-operator recursion

## Frozen question
Can the frozen V30 router/runtime use the verified success of its own first synthesized natural SAIR probe to induce a reusable probe operator, retain that operator in explicit developmental state, and later use it to repair a fresh successor-state epistemic obstruction without a manual controller handoff?

## Frozen theory
Do not change commitment routing. V31 tests only the next epistemic scaffold exposed by V30.

A verified synthesized probe may induce a structural operator from the relation between the new probe and an already installed probe. The operator is admitted only after a lawful verified probe transition and is stored in state/Lawbook. Later synthesis may instantiate retained operators.

No protected SAIR TRUE/FALSE answer may enter routing, operator induction, operator expansion, incidence, state update, or evidentiary world selection.

## Natural corpus
Official public SAIR Stage-2 `normal`, `hard1`, `hard2` development rows, exactly as in V30.

## Stage 1
Reproduce the V30 one-machine trace from an answer-blind natural commitment-defect cell:

`DEVELOP_PROBES -> synthesized order-3 model-existence probe -> verified split -> ACT -> nonterminal proof-frontier successor`.

The runtime synthesis registry is additionally given a generic operator inducer. It may inspect only probe syntax/metadata and the verified transition record. It may not inspect problem answers.

## Operator induction
If the successful synthesized atomic probe differs from an already installed same-direction atomic probe only in its integer order literal, induce the reusable structural macro

`NUMERIC_LITERAL_SHIFT(delta)`.

The macro identity must not contain a problem id, cell id, answer, or target order name. It is retained in explicit developmental state.

## Successor obstruction and old-language audit
On the nonterminal successor state, first audit the frozen pre-operator V28 probe extension carrier with an ablated registry that has no learned-operator expander.

If that old carrier can still repair the successor commitment defect, operator use is not licensed and V31 must report `OLD_PROBE_GRAMMAR_STILL_VIABLE` rather than forcing promotion.

Only if the old extension carrier is exhausted may the retained operator be used.

## Recursive operator use
The learned `+1` numeric-literal operator is applied to installed probe programs. The natural recursive target is an order-4 model-existence query produced by applying the learned shift to the installed order-3 probe. There is no named `ORDER4`, `SUCC2`, or hand-authored order-4 constructor.

Order-4 model-existence outcomes are computed exactly with the existing bounded-model verifier; every SAT table is independently rechecked and UNKNOWN is disallowed for an evidentiary pass.

## Gates
1. V30 stage-1 router still selects `DEVELOP_PROBES` before synthesis.
2. First probe is executed lawfully and verifier-only state update occurs.
3. A reusable numeric-literal-shift operator is induced automatically by `SynthesisRegistry`, not experiment code.
4. Operator is retained in explicit state/Lawbook.
5. First continuation is nonterminal and produces a first-class successor residual.
6. Pre-operator old probe extension carrier is exhaustively audited on that successor.
7. Operator promotion proceeds only if the old carrier is insufficient.
8. Second probe extension is generated by the retained operator and is absent from all pre-operator probe candidates.
9. Second probe is independently verified; all order-4 SAT witnesses used are rechecked and no UNKNOWN occurs.
10. Second verified probe changes the successor observational quotient and restores a common lawful continuation.
11. Ablating the retained operator restores the successor probe-language obstruction.
12. Wrong-sign numeric shift (`delta=-1`) does not repair the same successor residual.
13. The second transition is causally downstream of the first: removing the first verified synthesized probe prevents induction of the operator and makes the second extension unreachable.
14. No protected answer is used in routing, induction, expansion, state update, or world selection.

## Claim boundary
A pass establishes bounded natural recursive epistemic development from program synthesis to reusable operator induction inside a supplied generic transition/operator interface. It does not establish mutation-grammar invention, raw experimental-interface construction, unrestricted probe-language invention, broad SAIR solving, or cross-domain transfer.
