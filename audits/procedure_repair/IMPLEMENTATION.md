# Implementation contract

This records the exact interpretation of the frozen protocol before running the experiment. The certificate checker has ordinary exact rational polynomial arithmetic and the soundness rules that sums and products of nonnegative quantities are nonnegative. These are checker semantics, not additional search operators. The only generated proof constructors are coefficientwise positivity, nonnegative monomial factorization, quadratic square completion, and compact-interval affine decomposition. The last constructor factors an exact polynomial into affine factors and checks each factor at both interval endpoints; it is a concrete implementation of the frozen interval-transformation operation, not a general polynomial positivity oracle. All identities are independently checked. No target-name dispatch is permitted.

The candidate procedure order is frozen as coefficientwise, half-line square, interval affine, then an intentionally insufficient coefficient-only sham. The first obligation is on [0,infinity); the second is on [0,1]. The selector sees only a verifier failure and the candidate procedures' accepted/rejected results. The procedure builder may inspect polynomial coefficients and domain endpoints but not the oracle's target name. Each promotion installs a callable certificate procedure, rather than only a proof of one instance. A generated certificate is replayed by a separate checker. A procedure is not promoted merely because it accepts the training polynomial: its generic soundness theorem must also pass Lean.

The held-out problem is a different positivity family, not an unseen instance of the same square-completion family. The test is bounded by these four procedure candidates, fixed domains, and the common two-promotion budget. A control that receives the same candidates and merely lacks a residual is not evidence of an advantage unless its measured outcome differs. No claim of a new physical theorem or a newly invented primitive is allowed.
