# ARC → Robotics Cross-Domain Compounding V1 — frozen precommit

## Question

Can a relational capability discovered from passive ARC-like examples causally reduce later active-world developmental cost when the target domain uses different observation tokens and an unknown polarity adapter?

## Source domain

Eight ARC-like symbolic examples enumerate all binary triples `(a,b,c)`. The output is generated by one unknown deterministic Boolean relation. The learner searches the complete frozen family of all 256 maps `{0,1}^3 -> {0,1}`. The source examples are constructed so the unique retained relation is 3-bit parity.

The retained capability is only the 8-bit truth table for that relation. No target labels, target instances, or target answers are available during source discovery.

## Target domain

A finite active world exposes three raw sensor bits through three paid probes. The correct terminal action is generated by either parity or complemented parity over those raw bits. Which polarity is used is chosen from a sealed seed derived from the executing commit SHA and GitHub run ID when available.

Target calibration presents the eight raw input triples in lexicographic order. Each calibration observation is paid. Target execution worlds are generated only after the sealed seed is fixed.

## Arms

- `COLD`: starts from all 256 target truth tables; exact identification requires the full 8-case calibration stream.
- `WARM`: starts only from the polarity orbit of the retained source parity capability. It may accept a unique candidate only after that candidate survives one additional independent confirmation observation.
- `SHAM`: retains the same type/size of capability, but the source truth table is 3-bit majority. It follows the same transferred-family protocol. When its family is contradicted it falls back to the cold family while reusing already-paid calibration observations.
- `ABLATION`: exact deletion of the retained source capability before target calibration; therefore follows the cold path.
- `RESTART`: serializes only the retained parity capability, discards derived target state, reloads it, and follows the warm path.

## Metrics

Primary developmental cost:

`operator_evaluations + paid_calibration_interventions`

Secondary:

- calibration interventions
- operator evaluations
- execution probes
- sealed target correctness
- UNKNOWN count
- source discovery evaluations

Execution probes are reported separately because every arm must physically observe the same three raw sensor channels on every sealed target world.

## Frozen primary prediction

The experiment passes only if:

1. every arm is exactly correct on every sealed target world;
2. `WARM developmental_cost < COLD developmental_cost`;
3. `WARM developmental_cost < SHAM developmental_cost`;
4. `WARM developmental_cost < ABLATION developmental_cost`;
5. `RESTART developmental_cost == WARM developmental_cost`;
6. `ABLATION developmental_cost == COLD developmental_cost`;
7. WARM and RESTART use exactly 2 paid calibration interventions;
8. COLD, SHAM, and ABLATION use exactly 8 paid calibration interventions.

## Interpretation boundary

A pass establishes only a finite causal transfer result under the declared shared relational family and polarity adapter: retained source structure reduces later target identification cost, the gain survives restart, irrelevant retained structure does not reproduce it, and exact deletion removes it.

It does not establish general ARC solving, ontology invention, MuJoCo performance, sim-to-real transfer, physical robot safety, or general cross-domain intelligence.
