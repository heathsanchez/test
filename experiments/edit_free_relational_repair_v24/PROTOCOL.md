# Edit-Free Relational Repair V24 — Frozen Protocol

## Dependency

V23 removed V22's pointwise SET primitive, but still supplied an explicit relation-incidence change operation:

    FLIP(p,q).

V24 asks whether even FLIP is necessary for repair acquisition.

## Question

Can a verifier-clean repair be discovered by constructing complete candidate relations directly from generic relation facts, with no edit operation at all?

The target is:

    current relation
      -> certified residual
      -> exhaustive direct relation construction
      -> globally minimum extensional change
      -> repeated difference structure
      -> prospective held-out difference prediction.

## Primitive constructive substrate

Let P be the finite presentation carrier.

A candidate transformation is a relation graph R subseteq P x P represented positively by generic facts:

    EDGE(source,target).

The declared candidate type is a total single-valued relation:
for every source p, exactly one EDGE(p,q) is chosen.

Candidate generation therefore enumerates every total map:

    P -> P.

This is a typed relation-construction language, not an edit language.

The frozen executable core contains no:
- SET;
- FLIP;
- toggle;
- assignment;
- redirect;
- swap;
- exchange;
- transposition;
- cycle;
- delta-application repair operator.

Bijection is not built into generation; it is checked by the independent verifier.

## Current relation and cost

The current transformation is identity I.

Candidate repair cost is measured extensionally after construction:

    d(R,I) = |R symmetric_difference I|.

This is a diagnostic/cost on two completed relations, not a primitive action language.

No candidate is generated by applying that difference.

## Current language and residual

As in V21-V23, first exhaust:

    L0 = Perm(X) x Perm(C)

on the reified carrier P = X x C.

Only after a certified witness

    V(a)=V(b)
    and
    orbit_L0(a) != orbit_L0(b)

may direct relation construction begin.

## Independent verifier

A constructed total relation is admitted iff:

1. it is bijective;
2. it maps residual source a to residual target b;
3. every graph edge preserves consequence;
4. its mapping lies outside exhausted L0.

## Global minimum

Enumerate all |P|^|P| total maps in the declared finite language.

Verify all of them.

Among accepted candidates minimize extensional relation distance d(R,I).

Preserve the full equal-cost minimum frontier.

Because the entire language is exhausted, the minimum is exact.

## Derived difference description

Only after a candidate relation has been constructed and verified, compute its extensional difference signature:

    Diff(I,R) = sorted(I symmetric_difference R).

This is evidence describing what changed.
It is not used to generate the training repair.

Represent the derived signature as:

    DIFF(
      EDGE(source_1,target_1),
      ...
    ).

## Generic abstraction

After two independent relabelled worlds produce verifier-clean minimum relations, structurally anti-unify their derived DIFF terms using generic first-order LGG:

- matching constructors recurse;
- equal constants remain;
- unequal constants become variables;
- repeated disagreement pairs reuse variables;
- incompatible shapes return NO_SCHEMA.

No relation-repair-specific abstraction rule is supplied.

## Prospective held-out prediction

On a third relabelled residual, bind the learned DIFF schema from the residual obligation.

This produces a predicted extensional change signature before held-out global relation search.

Then independently perform the full cold relation search.

The predicted signature passes only if it exactly equals the extensional difference of a globally minimum verifier-clean held-out repair.

This separates:
- acquisition of the repair by direct relation construction;
- later compression of recurring change structure.

## Minimal Developmental Algorithm

The governing loop remains:

    EXECUTE
    -> VERIFY
    -> DIAGNOSE
    -> CONSTRAIN
    -> RESTRUCTURE
    -> CHOOSE
    -> COMPILE
    -> UPDATE.

## Required post-freeze gates

### E1 — no edit primitive
Frozen executable core contains relation construction and extensional comparison only; no SET/FLIP/toggle/assignment/redirect/swap-like repair primitive.

### E2 — complete direct relation construction
The main world exhausts every total map P->P in the declared finite language.

### E3 — exact minimum extensional repair
At least one verifier-clean repair exists and its global minimum distance from identity is > 1.

### E4 — repair is verifier-derived
All minimum accepted relations are bijective, discharge the residual, preserve consequence, and lie outside L0.

### E5 — independent relabelled recovery
A second independently relabelled world independently recovers the same minimum distance without using the first repair.

### E6 — generic anti-unification of derived differences
The two independently constructed relations yield a non-ground recurring DIFF schema with repeated variable structure.

### E7 — schema is strictly more abstract
The learned DIFF schema contains fewer concrete presentation constants than either training difference and re-instantiates both exactly.

### E8 — prospective held-out difference prediction
Before held-out cold search, schema instantiation predicts a concrete held-out difference signature from the residual alone.

### E9 — held-out cold search confirms prediction
Independent exhaustive held-out relation construction finds a globally minimum verifier-clean relation whose extensional difference exactly matches the precomputed schema prediction.

### E10 — wrong consequence binding fails
Binding the schema to unequal-consequence endpoints must not match any verifier-clean repair.

### E11 — no residual, no relation construction growth
If L0 already realizes consequence equivalence, no repair construction or schema growth is authorized.

### E12 — relation composition remains exact
The independently constructed repair participates in generic relation/function composition while preserving bijection and consequence.

### E13 — incomplete authority
Missing consequence values return UNKNOWN_AUTHORITY.

### E14 — verifier ablation
Without verification, no constructed relation is admitted.

## Scientific interpretation

A pass establishes, in a bounded finite setting:

> repair acquisition does not require a primitive edit instruction. Complete transformation relations can be constructed directly from generic relational facts and selected by verified consequence plus minimum extensional change. The recurring edit-like pattern can then be observed and compiled after the fact.

This would make V23's FLIP a convenience rather than a necessary acquisition primitive.

## Claim boundary

A pass does NOT establish:
- unrestricted relation construction;
- that total-map typing is generated rather than supplied;
- continuous transformations;
- physical or quantum symmetry;
- autonomous invention of the verifier.

The next boundary is the type itself:

    can total/function/bijection structure be consequence-earned
    from unrestricted finite relations rather than supplied as candidate typing?
