# V2: Necessity of a new consequential observation — pre-native execution protocol

## Scientific goal
Discriminate two native systems sharing all values of the DECLARED passive observation interface but differing on the outcome of one normatively required behavior. Compile a minimal additional action probe from source-authoritative schema metadata and a separately supplied requirement.

## Status and lineage
Prior SQLite World Compiler and V1 Consequential Obligation Compiler were bounded GREEN, with a CHEAPER fully informed PRAGMA baseline. This experiment asks whether passive readouts are ever insufficient. It is a NEW controlled native experiment on already exposed SQLite, not independent external-source transfer or G2 invention.

## Explicit external requirement
SOURCE_REQUIREMENT_1: negative values must be rejected by the relevant source-declared CHECK policy. This is independent **researcher-authored synthetic normative authority**, NOT a discovered upstream author requirement. The table name and guarded column are not supplied to the witness compiler.

## Protected test design
Two source-generated schemas (distinct table/column names) both declare CHECK(policy_ok(column) = 1). A registered SQLite user-defined function implements either compliant (negative values rejected) or noncompliant (all values accepted) behavior. Each pair shares exactly the same sqlite_master and declared PRAGMA passive readouts. Introspection of Python function source/registration and PRAGMA function_list are outside the passive authority boundary, and this restriction MUST be disclosed.

## Selection
Compiler parses the source schema and separately supplied negative-value requirement to construct one rollback-only orphan/negative insert (value -1), without seeing function behavior or mode. The same operation must be valid for both schemas; fail closed otherwise. The physical experiment must preserve row count. A single negative-input probe does not prove universal policy enforcement.

## Fair baselines and controls
Passive-only conventional baseline: cannot distinguish worlds with identical passive observations; UNKNOWN.
Fully informed intervention-capable baseline: competent reviewer can choose exactly the same value -1 insertion at equal or better cost. TIE, not superiority.
Independent native oracle: compare against actual SQLite outcomes in paired modes, not compiler self-labeling.
Withdraw normative requirement -> UNKNOWN. Restore -> exact same proposal. Retain unchanged existing claims, no new R7.2 / CLC proofs, no use of MathGraph Check runtime.
No unseen source, no target-specific post-failure change, no economic superiority or generalization claim.

## Decisive success
Same permitted passive evidence; different native behavioral responses; one compiled admissible witness separates them without persistent writes; equally informed baseline compared honestly. This warrants necessity of acquiring a non-passive observation **relative to the declared passive observation language**, not unrestricted necessity or independent semantic acquisition.
