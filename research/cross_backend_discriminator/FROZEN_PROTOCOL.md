## Frozen reusable operator before implementation
Build *one* generic `cross_implementation_consequence_discriminator` with:
- JSON declarative probes listing **two original independently executable implementations** that purport to implement one shared operation, plus an immutable source SHA/revision for each. Support three experiment arms: reference, base, contributor-head.
- Never write source-specific implementation logic in the discriminator; require native original compiled programs or original upstream interpreter binaries. A human-written manifest/transport adapter may state the target query grammar and CLI invocation, but this counts as **human authored semantic targeting** and does NOT qualify autonomous L7 generator invention.
- Use a bounded, **generated input domain**, not only the exact published failing input: for gojq enumerating strings/separators over a small declared alphabet and lengths; for OPA extend a declared metamorphic permutation/substitution input family, without editing original code. Automatically execute same inputs on both implementations, compare normalized typed results, emit first witness and attempt minimization, then repeat under author-head and all-negative non-witness controls.
- Keep `TIMEOUT`, `PROCESS_ERROR`, `BAD_OUTPUT`, `SOURCE_PIN_MISMATCH` distinct from genuine semantic `VALUE_MISMATCH`. A timeout is NOT a mathematical proof of nontermination.
- Report original native source run, commands, environments, exact revisions, machine elapsed/cost, all observed output digests, statuses (WARRANTED_BOUNDED, UNKNOWN, REFUTED_BOUNDED as appropriate). Disallow cross-PR evidence attribution, reject stale/withdrawn source and permit hard restart/cache-ablation with identical result.
- Strong baseline B = **fully informed competent conventional differential tests** using the SAME declarative manifest / source revisions; any algorithmic advantage must be measured vs this, not against green CI only. Human review time NOT MEASURED; upstream PR description already gives the original defect. Report baseline parity or losses as negatives.
- Pre-declared success A: generic engine with no target-specific branch changes runs original OPA and original gojq/jq source; produces at least one originally failing base→reference input and the corresponding healed head→reference case, no false positive on benign controls, reproducible after restart. *This only establishes bounded portability of a human-written, declarative evaluator*. Success B (autonomous method-generation/new source semantics or economic superiority) **remains UNKNOWN** unless actually observed with stricter new-source controls.
- If native CLI cannot compile, if source pin changes, if original reference behaviour is ambiguous, or if the second case cannot be processed without per-target algorithm edits, return UNKNOWN/FAILED; do not substitute a different target after seeing outcome.
