Frozen before any V15 compiler code. Parent V14 source-to-consumer exact-head GitHub Actions #38204583207 (head 024135d8ebe2318d88ffe9e5ff0768ae6ca357c2).

## Exact residual
V14 spent 6,656 raw feasibility/score reads establishing applicability for five protected solutions whose guarded solver required just 1,198 feasibility calls. Revalidating the same structural law for each new task can overwhelm the benefit of retained capability.

## Hypothesis
From an *opaque finite hereditary source oracle*, derive the unique antichain of minimal forbidden subsets, compile it as an exact typed source-level predicate, and qualify the general rule:
  allowed(S) iff no forbidden witness P is a subset of S.
Together with a *typed nonnegative modular score constructor*, this provides a reusable sufficient interface. Compiled source provenance should permit future task instances to be admitted without exhaustive per-task raw readout scans, provided the same trusted constructor schema and independent source qualification still apply. Any opaque untyped score/function has no such warrant and remains UNKNOWN.

## Freeze boundary
1. Commit source-oracle tasks and a separately authored protected structural-task generator, including generator seed, positive and negative cases and exact interface grammar, **before** implementing the compiler/consumer. No protected data may be used for rule discovery.
2. Source phase learns minimal obstructions from **source oracle observations only**, checks heredity by complete finite enumeration, and emits a source-bound generic constructor with checked size/index boundaries. No hardcoded protected patterns.
3. General constructor finite qualification: exhaustive all possible collections of nonempty forbidden patterns on n=4 (2^15 collections) plus independent randomized n=7 families. Guard law source promise and mutation controls. This is exact finite validation, not a Lean proof of all natural n.
4. Future tasks use only a typed forbidden-hypergraph contract and a trusted compiled source schema, never raw arbitrary Python callbacks. Fast applicability guard checks schema, indices, source hash and weights, not each subset. Outside-schema score changes, negative weights, invalid pattern indices and counterfeit source identifier fail closed.
5. Independent target oracle calculates every subset, checks all printed answers, causal ablation and revocation. Benchmark 1,024 frozen target tasks (including negative cases) and compare FULL acquisition + future guard costs versus legacy V14 per-task exhaustive guard. Count source constructor certification separately from readouts; avoid falsely treating cheap integer comparisons as equal to costly external measurements.
6. Compare to an equally informed stateless typed-schema validator that can apply the same mathematical law (expected exact tie), and to a deliberately stronger complete original-oracle baseline. No new invention of universal constraint syntax, strict universal advantage or unconditional recursive intelligence is claimed.
7. Independent exact-head GitHub Actions and durable receipt required before warranted promotion.

## Decision
Pass requires exact source qualification, 100% protected positive/negative correctness, restart/revocation and no legacy silent acceptance. Claim positive **lifecycle** amortization only under an explicitly priced metric and a sufficiently repeated family; report the source one-time proof cost and historical V11/V12 discovery costs separately. If even this guard compiler cannot reduce lifetime cost, reject incremental economic promise in this finite world.
