## Candidate review finding
**Severity candidate: Medium (conditional UI reliability / pagination loss).** When an audit list page is loaded, a newer audit event arrives through SSE, and a subsequent offset-based page query overlaps the previously loaded data, `setEntries` concatenates the duplicate and counts it as a separate entry. The UI computes `hasMore` by `entries.length < total`, prematurely reports completion, and never loads the oldest remaining audit item. Distinct duplicate rows can appear. User-visible effect is incomplete audit trail when live updates interleave pagination. This is supported by an explicit source-derived temporal/collection consequence contract; it does not allege that every server update schedule produces the failure.
