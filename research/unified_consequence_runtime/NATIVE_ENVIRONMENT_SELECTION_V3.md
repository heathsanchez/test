# Native environment admission v3

This is a versioned extension of the preserved v2 admission, provisioning, verifier and runtime sources. It does not change their previous warrants or results. The wrapt and more-itertools cases are exposed development diagnostics, never prospective successes.

The operation statically derives interpreter and dependency constraints from original source metadata, requirements and pytest configuration. It selects only from the externally frozen two-profile catalog. Ambiguous, dynamic, unsupported or unsatisfied metadata returns UNKNOWN. A selected profile is a candidate environment, not a scientific warrant.

The controller independently freezes executable and standard-library file bytes before target access. Child interpreters must match those bytes and the exact selected version. Pinned dependency installation requires the catalog wheel hashes. Installed pinned dependency files are checked before and after the original project build; the build cannot silently replace them. Original tracked production and test bytes remain authoritative.

The portable child worker retains the frozen v2 collection, execution and independent replay algorithms in isolated bindings. Its explicit changes support Python 3.6/pytest 5 and modern Python/pytest without weakening source, import, test-code, plugin, required-assertion, exact collection, skip/xfail or JUnit checks. Loadable standard-library symlink directories are refused. Native launch attempts remain charged when producer evidence is malformed.

The first gate requires nonzero complete native execution of both diagnostic suites, protected assertion failures, and an independent native repetition. Fixture contracts exercise missing, skipped, deselected, altered, forged, wrongly imported and dynamically registered tests. A green admission workflow establishes this bounded admission operation only. G2, G3, G4, generic Python-runtime refinement proofs and non-bypassable external containment remain UNKNOWN until their separate gates pass. Interpreter identity covers the executable and declared standard-library roots; it is not a proof of the entire operating-system image or an agent sandbox.

After this gate, the prospective controller requires a separately committed metadata universe, outcome-neutral independent admission screening, sealed future evidence and a fresh runtime freeze. It retains the original MSI/V104 policy and tie/UNKNOWN behavior. Every screened refusal is retained and charged; admitted native PASS and FAIL have identical screening eligibility. A training task with no residual stops the experiment rather than being replaced.

The original E/D/V54 state, 246 ledger records, 76 content-addressed objects and 70 inventory rows must remain exact. Acquisition does not create external permission. No G3 claim follows from environment selection, runtime fixtures, or a successful G2 test.
