# V43 prospective binding acceptance freeze

This is a wiring extension to the existing V42 prospective controller, not a new search framework. No target is queried or frozen by preparing these controls. A fresh source universe is allowed only after the complete native interface gate has an independently audited archived Actions artifact. Original V42 sources, protocol, screening evidence and results remain unchanged.

## Two production modules

`native_environment_v43.py` delegates original V42 source transport, metadata-only environment selection, pinned-package provisioning, base-wheel installation and source/authority checks. Its `provision(spec, root, protocol_binding, *, catalog, runtimes, machine, collection_seconds=60, execution_seconds=600)` requires the existing V43 Machine explicitly. A successful original setup is projected into the explicit V43 contract/policy schema before collection.

For the recognized immutable original Hatch VCS declaration, register a source frontier once the exact augmented contract, original base authority and full actual target environment are known. Admit/activate the same generic `source.materialize_declared_backend` opcode with fresh backend build and independent rebuild for this exact environment; attach its evidence as `contract.generated_build` and return its capability under `materialization_capability`. The qualification fixture's exact environment scope is not assumed to cover a newly provisioned target venv. Installed target packages, backend/interpreter and standard-library identity remain actual authority inputs. Every attempt is charged. No repository, task, generated path or winning patch selects the method.

Unsupported backend/declaration keeps the explicit tracked-only `generated_build=None` path when original native admission is applicable, or yields a precise UNKNOWN. There is no fallback to unverified generated imports or synthetic version metadata. Registering an interface frontier does not warrant native success.

`qualify_native_frontier_v43.py` privately binds the original Q42/Q3/Q2 algorithms to the V43 environment, worker, Machine and runtime. `orders`, constructor `catalog`, fixed-order PASS/FAIL eligibility, original search bytecode, candidate grammar, eight-proposal horizon, 512 native-call/3600-second meters, protected-future release and scientific verdict rules preserve their existing semantics. The physical-removal counterfactual also constructs V43 Machine so original FLASH can reclose retained materialization records.

## Explicit screening authority and pre-source obligation

The outer CLI authority schema is `UDM_NATIVE_CLI_AUTHORITY_V43`. A screen ticket adds exact `machine_components` fields `path` (canonical components root) and `pins_sha256` (SHA256 of the unchanged `developmental_sources.json`). `_screening_components(ticket, descriptor)` reads the exact committed authority descriptor, rejects differing ticket bytes/schema/pins, validates the canonical path, and returns that path. It does not select components from ambient environment variables. Original Machine initialization checks actual component commits and all pinned bytes.

`admission_only_screen(spec, destination, binding, *, catalog, runtimes, components)` keeps the ordered screen's original baseline-only behavior. It first creates its new case directory, constructs a real V43 Machine under that directory, and records `native_admission_request_v43` with `spec_sha256` and the unchanged `authority_ceiling`. This node precedes environment provisioning and source/native effects. The exact source-materialization frontier is registered later when the contract exists, before `worker.collect`. `execute_screening_request` supplies components only from its committed ticket. The existing once-only order, refusal retention and native-call ceiling remain intact.

The new protocol/freezes/results and metadata/prequery/screening records live in a new V43 record directory and bind exact source lineage. They do not rewrite V42 record paths or outcomes. Gate validation requires the archived whole V43 interface result, unchanged original environment/catalog authority, actual frozen runtimes, source files including these two bindings and their tests, all scientific G2–G6 verdicts UNKNOWN, and an independent artifact audit. Qualification success is admission evidence only.

## All integrated worker paths observe support

`_prepare` keeps its original body with narrow reviewed binding sites: import `native_runtime_v43.NativeRuntimeV43`, pass `machine=machine` to environment provisioning, and pass `materialization_capability=setup.get('materialization_capability')` to runtime construction. Its collection and native probes use the live exact witness.

Original independent profile reconstruction and coding-agent execution call the worker directly. They therefore require two small preflight helpers in the new controller:

- `_preflight_record(record, machine)` runs before **both** cache lookup and uncached `checked_record` reconstruction. It checks exact live materializer generation/request/evidence and original source lineage before any new independent worker launch or cached result use.
- `_preflight_agent(arm)` reconstructs the exact sealed Machine/components/state/instrument context from the agent parent binding and checks live source support before `_execute_agent_candidate` reaches direct worker verification/replay. It does not invent a native outcome or change agent proposals/meters.

For generated contracts, native probe events retain the materializer as an explicit causal dependency. The same dependency prefix is normalized in episode checks, preserving caller policy dependencies and original order/budget tests. Independent reconstruction must not turn a source-admission UNKNOWN into FAIL_NATIVE. Missing executable/evidence or withdrawn support refuses before a producer starts.

## Frozen test scope

`test_qualify_native_frontier_v43.py` checks function/code bindings, strict committed component authority, real Machine/Metatron/FLASH initialization and pre-provision obligation ordering, live-witness preflight on cached/uncached profiles and agent candidates, and unchanged PASS/FAIL fixed-order eligibility. Dependency doubles only stop at explicit wiring boundaries; they never supply a native PASS/FAIL receipt. These unit controls do not claim end-to-end source provisioning or a scientific result. Existing real Hatch build/native/causal integration controls remain responsible for actual native assertions, generated provenance, withdrawal and restart.

Run these tests as an additional whole-interface gate input after their actual preimplementation RED is committed. Keep original source/environment constraints and exact per-target-environment materializer evidence; do not broaden the qualification fixture's scope to make a target pass.
