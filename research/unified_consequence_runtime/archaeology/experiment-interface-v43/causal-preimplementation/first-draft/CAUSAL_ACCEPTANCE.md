## Concrete interfaces

- `developmental_machine_v43.Machine(components, state, evaluator, config)` preserves the original Machine, Metatron and FLASH authority. Versioned core bindings license only the new materialization checker; original generic-native frontier publication remains unavailable.
- `native_materialization_v43.request(contract, authority, policy)` returns a deep-copied strict JSON object with exactly `schema`, `contract`, `authority`, `policy`. Schema is `UDM_NATIVE_MATERIALIZATION_REQUEST_V43`. The twelve-field V43 contract has `generated_build=None` before materialization. No caller-generated path allowlist is accepted.
- `MaterializationRuntime(machine, output)` uses the existing Machine CAS and causal log. `register(frontier_id, request)` registers the protected obligation before admission. `admit(request, *, supersedes=None)` performs actual fresh preparation and independent verification, retains the executable, and publishes its typed route. `_validated(capability_id)` checks retained executable source/program, CAS, evidence and liveness before a producer starts.
- The capability operation is `source.materialize_declared_backend`. Its executable program and scope describe the original Hatch VCS backend class, recipe, frozen environment and unchanged external authority ceiling. They contain no fixture repository, source commit, package identity or generated path. Exact source identities belong to invocation requests and evidence.
- `execute(capability_id, request)` returns `(build_evidence, consequence_id)` after a new prepare and independent rebuild for that request. The original builder's four-function API remains authoritative. The verification node and materialization consequence each retain their receipt under payload key `receipt`; the actual wheel and raw receipt trees persist.
- `Machine.select_and_execute_frontier(frontier_id, materializer)` uses the retained request. An unresolved frontier returns `UNKNOWN_SEARCH` without acquisition/build/native execution. A resolved route returns `status="READY"`, `capability_id`, `materialization` (build evidence), and `consequence`.
- `restore(capability_id, request)` requires a withdrawn instrument, fresh independently checked evidence, a new generation and explicit `supersedes`. It preserves the generic executable program. Old descendants remain withdrawn.
- `native_runtime_v43.NativeRuntimeV43(machine, contract, authority, certificate, policy, output, *, materialization_capability=None)` preserves the original native adapter API. A generated contract requires the live exact materialization capability; a tracked-only contract explicitly uses `None`. Native source/scope binds instrument generation and generated evidence. Admission automatically records the instrument as a causal premise. Observation, probing/search through `_verify`, admission and execution preflight the dependency before any producer launch.

The existing worker `collect(contract, ...)` API has no Machine argument. These tests qualify the integrated Machine/runtime routes, not a hostile-process reference monitor over direct public Python calls. Original source/Git validation subprocesses may run during refusal; no build, collection or native execution producer may run.

Retain a native capability, a dependent native child and a verified consequence, each causally supported by the materializer.
