# Native admission v2: formal and authority boundary

This continuation qualifies admission infrastructure, not developmental intelligence.
It preserves the predecessor's E/D/V54 warrants and their original proof boundaries.
No new Lean instance, Python refinement proof, universal search obstruction, or
external-agent containment theorem is established by admitting a pytest suite.
The existing [formal correspondence](../../FORMAL_CORRESPONDENCE.md) remains unchanged.

## Concrete native contract

The versioned extension binds independently authenticated Git source, original
pytest configuration, exact author-test bytes, interpreter and installed
package identities, explicitly licensed plugin bytes, protocol, and execution
budgets. Static declarations supply protected node prefixes. The independent
original-source collector supplies the complete parameterized node set and its
source/code identities. Neither authority substitutes for the other.

The static class grammar recognizes immutable pytest class/function patterns,
`unittest.TestCase` imports and aliases, and closed local C3 inheritance. Mixin
methods are bound to every concrete descendant on which their effective method
binding is collected. A changed test-like declaration with no collected route,
a protected unresolved base, or unsupported nested class test mapping remains
UNKNOWN. Literal/container `test_*` data does not constitute test registration.
Dynamic registration and source/configuration overlays remain refused.

A candidate must execute the same complete collected suite. Missing, skipped,
xfailing, deselected, duplicated, changed, incorrectly imported, or otherwise
unbound tests cannot support PASS. Native FAIL requires real executed failing
calls; collection failure or nonexecution remains UNKNOWN. Admission-certificate
validation recollects original source independently. Independent receipt
validation re-executes the candidate natively rather than trusting a resealed
producer receipt. Source files changed after import invalidate the loaded
versioned authority instead of relabeling cached code with new file hashes.

These are executable checks under declared trust assumptions: the source
transport and Git identities are authentic; the pinned Python/pytest/plugin
implementations and host execute as specified; the native assertion suite is an
adequate bounded contract; and independent verifier/controller state is not
controlled by a hostile in-process adversary. Finite bypass controls do not
prove those assumptions universally.

## Explicitly separate verdicts

* Prior G0/G1: retain the exact historical qualified authority.
* Admission: requires independently checked exact collection, real native
  execution, protected failure, and fail-closed adversarial controls in the
  committed qualification artifact.
* G2/G3/G4: UNKNOWN until newly frozen untouched tasks are actually executed with
  the existing UDM and matched comparisons. Exposed diagnostics cannot qualify
  prospective selection, discoverability expansion, or comparative advantage.
* G5: UNKNOWN for this versioned native admission/runtime correspondence.
* G6: UNKNOWN for non-bypassable external-action enforcement.

The v2 runtime's original Metatron/FLASH support closure is reusable. Its new
versioned source checker is not licensed by the predecessor's typed-frontier
publication registry; that publication path explicitly refuses with UNKNOWN.
Admission therefore does not claim new cross-frontier publication portability.
