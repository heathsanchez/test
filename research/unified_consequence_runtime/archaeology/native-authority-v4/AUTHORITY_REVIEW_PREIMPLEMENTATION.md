# V4 authority review before implementation

Independent source review, 2026-10-16. Baseline: `95029db0`; requested branch: `research/udm-native-authority-v4-20261016`. This review reads the frozen V3 selector, environment, execution, admission and qualifier definitions and the V3 audit procedure. It does not inspect a new frontier, task metadata, task source, or new task outcomes. No native collection, native execution, environment provisioning, search, acquisition or constructor is authorized by this review. Native G6 remains **UNKNOWN**.

## Nonnegotiable authority

1. **Source identity is complete and byte based.** Preserve every existing tracked file. Retain exact commit/tree identity and the complete regular-file inventory: canonical path, mode, Git blob ID, raw-byte SHA256 and file count. All files belong in the source inventory, including files outside a semantic parser's scope. Inventory must not parse every `.py` file or require an `all.py` parse. A scoped parser's accepted files are not the source-identity boundary. Reject symlinks, submodules, path aliases and unavailable source; never silently omit them. Pin the frozen controller/admission source and the exact new implementation separately. A live module hash alone does not establish an independently committed authority.
2. **Original source and author tests stay authoritative.** Source metadata selection and native materialization must have identical base identity. The augmented source equals the complete base overlaid with exactly the permitted author-test blobs, with original production/configuration bytes and modes preserved. Bind author transport to repository, exact head commit, path, raw decoded bytes, length and hashes. Never transport repaired head production as a substitute. Candidate replacements must satisfy the unchanged production-only grammar and original-blob hashes; test files, collection configuration and setup authority cannot become candidate edits.
3. **Environment selection grants a candidate only.** Reconstruct selection from complete original bytes and the independent finite catalog; preserve the source fingerprint. Unsupported, dynamic, conflicting, unresolved, ambiguous or unsatisfied metadata remains UNKNOWN. Interpreter implementation/version, executable bytes, original standard-library inventory and exact package artifacts/files must stay independently pinned, including before and after project build. An absent package/version/plugin cannot be repaired by guessing from the host, installing an unlicensed alternative or selecting a different profile after an outcome.
4. **Native collection is independent and exact.** Static protected prefixes do not prove native collection, assertion strength or execution. Require nonempty unique complete parameterized node IDs, equal collected/selected membership, retained selected order, no deselection/collection errors, exact original test-source and callable-code identity, and coverage of each protected prefix. Preserve the original collection and selected orders separately: an original fixture may reorder; candidates must reproduce both exact orders. A renamed, missing, extra, skipped, deselected, forged or dynamically substituted test cannot earn PASS/FAIL authority.
5. **Import and plugin identity stay bound.** Independently verify pytest's installed distribution/version and import bytes. Bind all actual tracked imports to the original/candidate byte map; reject external imports of project roots and unexpected source changes. Retain the executable environment fingerprint and plugin inventory throughout certificates/receipts. Plugins require the independent module/distribution/exact-version license and distribution-file identity; registered plugins must be original source, licensed plugins or the frozen pytest core. Missing licenses, altered plugin bytes, changed plugin manifests and dynamic unauthorized registration remain UNKNOWN.
6. **Assertions must actually execute.** Bind exact setup/call/teardown sequences and counts to the selected collection, unchanged test callable code, process outcome and JUnit. PASS requires every call to pass; FAIL requires actual failing calls and matching process/JUnit failure evidence. Setup/teardown failures, errors, empty/partial execution, skip, xfail, xpass or missing protected execution remain UNKNOWN. A protected-prefix mapping does not prove semantic assertion strength or universal correctness. Qualification of a development diagnostic requires the frozen protected actual-call failure and independent complete repetition; it cannot establish a new frontier result.
7. **Replay and receipt evidence cannot be weakened.** Bind schema/revision, contract, authority, policy, runner, environment, plugins, source, candidate and raw packet hashes. Compare producer and checked records after removing only documented controller-added fields; retain exact native evidence and refusal artifacts. Independent execution agreement may remove only the documented top-level execution `costs`; never remove test order, code hashes, imports, plugins or outcome fields to force agreement. Bind every retained packet to disk bytes, not just self-declared hashes.

## Audit boundary and limitations

The frozen audit procedure is `../native-environment-v3/AUDIT_PROCEDURE_REVIEW.md`. Its safe retained-receipt entry point is `validate_receipt(..., independent=False)` on retained evidence, separately per receipt. That still snapshots local Git, starts environment/plugin identity subprocesses and uses temporary XML scratch files. Charge that work separately. `validate_certificate(..., output_dir=None)` **recollects**; do not invoke it during structural review. Neither `collect`, `verify`, `_run`, provisioning nor `validate_receipt(independent=True)` is a structural-only API. A retained certificate's structural portion must be checked explicitly without recollection.

Before/after native attempt snapshots must have zero audit deltas. Native counters exclude identity subprocesses, installs/builds, transport, audit overhead and engineering work; a zero native delta is not a zero-process or total-lifecycle-cost claim. Missing executable/runtime evidence remains an explicit limitation. Hash consistency is not independent execution attestation. Original tests and licensed plugins remain trusted Python and external enforcement remains `UNKNOWN_NONBYPASSABILITY`; Native G6 remains **UNKNOWN**. This review makes no new task verdict.

Git reads use `GIT_OPTIONAL_LOCKS=0`. Record actual index bytes or raw-byte SHA256, size and explicit absence **before** the first Git read and again after all relevant reads, for the common Git directory and every linked worktree administration directory. The absence of the common bare index is evidence, not a reason to omit it. Include an inherited alternate `GIT_INDEX_FILE` if present. Report creation, removal, content or inventory changes. Never reset, refresh, restore or rewrite an index to conceal a difference; preserving only a post-reset hash is insufficient. Index equality establishes index preservation, not complete repository immutability. Concurrent work is a stated limitation of an interval measurement.

## Minimal review tests

| Boundary | Required regression evidence |
| --- | --- |
| Complete identity with scoped parsing | Changing any inventoried file changes source identity; an unparsed/non-scope `.py` remains hashed; an irrelevant invalid `all.py` is not parsed. Canonical paths/modes and complete path-set changes fail closed. |
| Original source/overlay | A changed production/config/test blob outside the authorized overlay is refused; the selected base and native base identities must match. |
| Exact collection | Missing/extra/duplicate/parameter-shifted/deselected nodes and changed selected order cannot become PASS/FAIL. Original fixture reordering remains bound. |
| Import/plugin | Altered or external project imports, substituted pytest, unlicensed/changed plugin registration or a changed plugin manifest are refused. |
| Assertion execution | An actual protected call failure is FAIL_NATIVE only with matching complete phase/JUnit/process evidence. Skips, xfails/xpasses, setup/teardown errors, missing phases, altered callable code and empty runs remain UNKNOWN. |
| Retained audit | Structural review launches no native or collection attempt, does not call the recollecting validator, checks packet/disk bytes and reports unavailable original-runtime evidence without reconstructing it. |
| Git index audit helper | Discover common and every linked index without invoking Git first; retain SHA256/size/absence for all, detect same-size changes and creation/removal/new worktree entries, read Git with optional locks disabled, preserve before/after evidence on command failure, reject mutating commands, and never restore/reset bytes. |

Use existing frozen fixture tests where they already cover these guarantees; introduce only the smallest missing V4 boundary tests. Keep the utility local and minimal. Preserve its observed RED output before implementation and GREEN output afterward. Broad test discovery is outside this independent review because it could execute unreviewed task/frontier paths.
